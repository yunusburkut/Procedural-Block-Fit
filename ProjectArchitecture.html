Blokfit — Project Architecture

General design reference  ·  Blokfit Unity Puzzle Project  ·  2026-03-31

1. What Is Blokfit?

Blokfit is a 2D puzzle game built in Unity (URP, 2D). The player is presented with a square board subdivided into triangles and a set of irregularly shaped puzzle pieces. Each piece must be dragged onto the board until every triangle is covered — completing the level. Levels are generated procedurally at runtime from a DifficultyConfig, or downloaded from a server, or authored manually in a built-in Level Editor tool.

4. Data Model

All level data is described by three serialisable C# classes in Blokfit.Core:

class LevelData
{
    GridData    grid;      // board dimensions
    PieceJson[] pieces;   // one entry per puzzle piece
}

class GridData
{
    int size;              // N — board is N×N cells, 2N² triangles
}

class PieceJson
{
    int[]  cells;          // triangle flat-indices: (row*N+col)*2+type
    string color;          // HTML hex e.g. "#FF6600"
    int[]  anchors;        // [0] = primary anchor (min flat index)
    float  spawnX, spawnY; // world-space tray spawn position
}

At runtime, PieceFactory.FromJson() converts PieceJson into the immutable PieceData record which stores piece-local TriOffset structs (column delta, row delta, type) relative to the anchor vertex.

6. System Deep-Dives

6.1 GameManager Blokfit.Core

The central orchestrator. Holds references to every system and wires them together via callbacks and C# events. Owns the undo stack and the game-state machine.

ResponsibilityHow
Default level on startupStart() calls BeginLevel(_easyConfig)
Level loading (3 paths)Server download → procedural generation → handmade JSON
UndoStack<ICommand> _commandHistory — pushed on every snap, popped by UndoLastMove()
Input blockingGameState { Idle, LevelComplete } → sets InputHandler.IsBlocked
UI wiringPasses lambdas to UIOverlay in Awake() — UI has no direct game-logic dependency

Handmade level scatter: The Level Editor exports pieces with spawnX = spawnY = 0. ScatterSpawnPositions() detects this and distributes pieces in an arc around the tray center with small random jitter, so hand-authored levels require no manual spawn coordinates.

6.2 BoardController Blokfit.Board

Owns the entire board state. Has no knowledge of dragging or UI — exposes only Place / Lift and fires OnBoardCompleted.

Internal structurePurpose
SnapPoint[vRow, vCol](N+1)² grid of vertex snap points
bool[row, col, type] _occupiedTrianglesWhich triangles are filled
PieceBehaviour[row, col, type] _occupantsWhich piece occupies each triangle
Dictionary<PieceBehaviour, List<(r,c,t)>>Reverse lookup — enables O(1) Lift without scanning the full grid
_filledTriangles counterIncremented on Place, decremented on Lift — triggers completion when equal to N²×2

O(1) snap-point lookup: GetNearestFreeSnapPoint(worldPos) converts world coordinates to fractional grid coordinates and rounds — no linear search needed.

Board shader: MaterialPropertyBlock pushes _GridSize to the board quad's shader so grid lines scale correctly without creating per-instance materials.

6.3 SnapSystem Blokfit.Board

Stateless service called on pointer-up. Finds the nearest free snap point, validates the placement, and if successful commits it and raises the command event. Uses squared distance for the threshold check to avoid a sqrt call. 

// Snap flow:
primaryAnchorWorldPos → board.GetNearestFreeSnapPoint()      // O(1)
distSq = SqrMagnitude(anchorPos − candidate.WorldPosition)
if distSq >= _snapThresholdSq: return false   // too far away
board.Place(piece, candidate)                                // validate + commit
piece.SetPlaced(targetPos)                                   // DOTween to snapped position
OnMoveExecuted.Invoke(new PlacePieceCommand(...))            // push to undo stack

6.4 SnapPoint Blokfit.Board

Lightweight MonoBehaviour at every grid vertex (N+1)². Stores its grid coordinates and world position. Edge points (col/row = 0 or N) are invisible; interior points render a faint white circle sprite shared across all instances via a static Sprite _sharedSprite — one texture allocation for the entire board.

6.5 Piece System Blokfit.Pieces

PieceFactory converts JSON flat indices into piece-local TriOffset structs:

// Flat index → (col, row, type) → subtract anchor → TriOffset
anchorCol = (anchors[0] / 2) % N
anchorRow = (anchors[0] / 2) / N

for each flat in cells:
    col    = (flat / 2) % N
    row    = (flat / 2) / N
    type   = flat % 2
    offset = TriOffset(col − anchorCol, row − anchorRow, type)

PieceBehaviour does five things at Initialize():

  1. BuildTriangleSprites — one child GameObject per triangle, each with a SpriteRenderer using a procedurally generated 64×64 triangle texture. The two textures (lower/upper triangle shapes) are static and shared across all piece instances — allocated once per play session.
  2. BuildCollider — sets one PolygonCollider2D path per triangle (3 vertices each). Unity's internal composite handles the full irregular shape.
  3. BuildAnchorTransforms — the piece's own Transform acts as the anchor; pivot is at local (0,0) which aligns with the anchor vertex on the board grid.
  4. BuildSnapDots — places 1–4 white circle dot visuals at interior vertices (vertices shared by ≥2 of the piece's own triangles). These fade in while dragging to help the player see where the piece will snap. The dot count uses a weighted random roll: ~80% → 1 dot, ~12% → 2, ~5% → 3, ~3% → 4.
  5. AnimateIn — DOTween OutBounce drop from Y=8 with a per-piece staggered delay (0.12 s × index) so pieces cascade into view.

Drag handling (Unity EventSystem):

EventAction
OnPointerDownAsk InputHandler.BeginDrag (gatekeeper). If allowed: lift from board, boost sort order (+1000), scale to 1.1×.
OnDragMove transform to screenToWorld(position) + _dragOffset. Camera-Z cached at init — avoids per-frame Transform access.
OnPointerUpCall SnapSystem.TrySnap. On snap failure: ReturnToTray (DOTween back to pre-drag position).

6.6 InputHandler Blokfit.Input

A stateless gatekeeper MonoBehaviour. Enforces two invariants:

  • Single drag — CurrentDrag != null blocks any new drag from starting.
  • Input block — IsBlocked = true (set by GameManager on level-complete) prevents all drag input.

DragState is a plain data struct holding the active piece reference and pointer ID.

6.7 Command Pattern (Undo) Blokfit.Commands

Every successful snap creates a PlacePieceCommand and pushes it onto GameManager._commandHistory (a Stack<ICommand>).

MethodAction
Execute()Calls board.Place + piece.SetPlaced. Used for re-do scenarios; not currently exposed in UI.
Undo()Calls board.Lift(piece) + piece.ReturnToTray(fromPosition).

The command stores: piece reference, board reference, world position before snap (fromPosition), world position after snap (toPosition), and the SnapPoint used — everything needed to replay or reverse the action.

6.8 UIOverlay Blokfit.UI

Unity Canvas overlay. Button listeners are registered in Awake(); callbacks are injected by GameManager — keeping UI completely decoupled from game logic.

ControlCallback injected by GameManager
Easy / Medium / Hard buttonsBeginLevel(easyConfig / mediumConfig / hardConfig)
Handmade buttonLoadHandmadeLevel()
Next Level button (completion panel)StartNextLevel()

Completion panel animation: "Done!" fades in over 0.5 s immediately; "Tap to continue" fades in after a 0.4 s delay — both via DOTween DOFade. On new level start, both texts are killed and hidden instantly.

8. Generation System

Procedural generation is a two-class pipeline (detailed in the companion document ProceduralGeneration_Algorithm.html). Brief summary:

ClassRole
TrianglePartitioner Randomised BFS flood-fill on an N×N×2 triangle grid. Forward-only cursor seed scan (O(T) amortised). Pre-allocated List/Queue buffers — zero per-call heap allocations in the hot loop.
LevelGenerator : MonoBehaviour Orchestrates partitioning, enforces piece-count and piece-size constraints via centroid-based nearest-neighbour merging, assembles PieceJson records with shuffled 16-colour palette and random tray spawn positions.

9. Level Editor (Editor-Only Tool)

Accessed via Tools ▶ Blokfit ▶ Level Editor (shortcut Ctrl+Alt+L). A custom EditorWindow that lets designers hand-author levels and export them as JSON fully compatible with the runtime loader.

┌──────────────────────┬──────────────────────────────────────────┐ │ Left Panel │ Right Panel (Grid) │ │ │ │ │ Grid Size N │ N×N triangle grid drawn with │ │ [slider 2-10] │ Handles.DrawAAConvexPolygon │ │ [Apply button] │ │ │ │ Left-click → assign tri to piece │ │ Pieces │ Left-click → toggle off (if same) │ │ [colour] Name [✕] │ Right-click → unassign tri │ │ [colour] Name [✕] │ │ │ + New Piece │ Selected piece highlighted +18% white │ │ │ Live triangle count per piece │ │ Active: ✔ │ │ │ X tri assigned │ Top: "Unassigned: N / M tri" counter │ └──────────────────────┴──────────────────────────────────────────┘ Toolbar: [Clear] [Export JSON] Warns before export if unassigned triangles remain

Export produces a valid LevelData JSON with:

  • grid.size = N
  • One PieceJson per non-empty piece (cells = assigned flat indices, anchor = minimum flat index, spawnX/Y = 0 — scattered at runtime by ScatterSpawnPositions).
  • Default save directory: Assets/Resources/Levels/. Immediately imported via AssetDatabase.ImportAsset.

10. Design Patterns

PatternWherePurpose
Command ICommand / PlacePieceCommand / GameManager._commandHistory Encapsulates placement as a reversible object; enables arbitrary-depth undo without coupling pieces to game state.
Observer (C# events) BoardController.OnBoardCompleted, SnapSystem.OnMoveExecuted Board and snap system fire events without knowing what will handle them — GameManager subscribes without the board depending on it.
Factory PieceFactory.FromJson() Converts raw JSON data into fully initialised runtime objects, isolating JSON structure details from game logic.
Flyweight (static shared sprites) PieceBehaviour._lowerTriSprite / _upperTriSprite, SnapPoint._sharedSprite One texture allocation per shape type regardless of piece count or board size.
Lazy Memoisation LevelGenerator._centroidCache Computes region centroids on first access and caches by array reference. Invalidated on merge. Avoids O(|region|) recomputation in nearest-neighbour searches.
ScriptableObject (Data config) DifficultyConfig Designer-editable parameters completely decoupled from code — swappable in the Inspector without recompile.
Gatekeeper / State machine InputHandler + GameManager.GameState Guarantees at most one piece dragged at a time; blocks all input during the completion screen.

11. Performance Notes

ConcernSolution
Per-frame drag allocation_screenToWorldBuffer Vector3 reused every OnDrag frame — no heap alloc per input event.
Triangle / snap-point texture duplicationAll triangle and snap-point sprites are static — allocated once per session regardless of piece count.
BFS heap pressure_carveResult, _carveQueue, _neighborBuffer are pre-allocated fields that are cleared and reused across all CarveRegion calls.
Unassigned seed scan costForward-only cursor _nextSeedCursor — O(T) total vs O(T²) naïve re-scan from index 0.
Centroid recomputationDictionary cache keyed by array reference — O(|region|) summation runs only once per unique array; invalidated on merge.
Snap-point nearest lookupO(1) round-to-integer formula — no linear scan over (N+1)² snap points.
Completion checkInteger counter _filledTriangles — O(1) increment/decrement vs O(N²) full scan.
Board shader stateMaterialPropertyBlock — pushes shader properties without creating per-instance material objects.
