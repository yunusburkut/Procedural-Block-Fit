Blokfit — Project Architecture & System Overview

Unity 2D Puzzle Game  |  C# / Unity  |  2026

1. Project Summary

Blokfit is a 2D puzzle game in which the player fills an N×N triangle grid by dragging puzzle pieces from a tray onto the board. Each piece is an irregular polygon composed of one or more right-angled triangles. A level is complete when every triangle on the board is occupied. Levels can be generated procedurally at runtime or loaded from hand-crafted JSON files.

3. Core Data Model

3.1 Level JSON Format (LevelData)

The canonical level representation is a plain serialisable object with two fields: 

{
  "grid":   { "size": 4 },          // N×N board
  "pieces": [
    {
      "cells":   [0, 1, 4, 5],      // triangle flat-indices
      "color":   "#FF2222",         // HTML hex
      "anchors": [0],               // primary anchor flat-index
      "spawnX":  -1.2,              // tray world position
      "spawnY":  -2.4
    },
    ...
  ]
}

Triangle flat-index encoding: flat = (row × N + col) × 2 + type, where type 0 = lower triangle (BL–BR–TR corners) and type 1 = upper triangle (BL–TR–TL corners). LevelSerializer wraps JsonUtility.ToJson / FromJson.

3.2 Runtime Piece Data (PieceData, TriOffset)

PieceFactory.FromJson converts absolute flat-indices into piece-local TriOffset structs — (dcol, drow, type) relative to the anchor vertex. This local representation is used at placement time to compute which board cells the piece occupies regardless of where it is dropped.

3.3 Difficulty Configuration (DifficultyConfig)

A ScriptableObject asset (created via Assets › Create › Blokfit › Difficulty Config) that stores: gridSize, minPieces, maxPieces, minPieceSize, maxPieceSize, and difficultyName. Three instances (Easy / Medium / Hard) are referenced by GameManager.

5. Game Loop

5.1 Startup

GameManager.Awake() → UIOverlay: wire button callbacks (Easy / Medium / Hard / Handmade / Next Level) GameManager.Start() → Subscribe to BoardController.OnBoardCompleted → Subscribe to SnapSystem.OnMoveExecuted → BeginLevel(_easyConfig) ← auto-starts on first run

5.2 BeginLevel (Procedural)

BeginLevel(DifficultyConfig config) → GameState = Idle (unblocks input) → commandHistory.Clear() → UIOverlay.HideCompletion() → PieceSpawner.DestroyAll() ← destroys previous level's GameObjects → BoardController.ResetBoard() ← clears occupancy arrays │ ├─ [if _serverBaseUrl set] │ Coroutine: HTTP GET {url}/{difficultyName}.json │ ├─ success → ApplyLevel(LevelSerializer.FromJson(response)) │ └─ failure → ApplyLevel(LevelGenerator.Generate(config)) [fallback] │ └─ [else] ApplyLevel(LevelGenerator.Generate(config)) ApplyLevel(LevelData) → BoardController.Initialize(gridSize) ← builds snap-point grid → SnapSystem.SetSnapThreshold(cellSize) → PieceSpawner.SpawnAll(pieces, gridSize) ← instantiates piece GameObjects

5.3 BeginLevel (Handmade)

LoadHandmadeLevel() → Read next TextAsset from _handmadeLevels[] (cycles with modulo index) → LevelSerializer.FromJson(asset.text) → ScatterSpawnPositions(levelData) ← distributes pieces on an arc if spawnX/Y == 0 → ApplyLevel(levelData) ← same finaliser as procedural path

5.4 Drag & Snap (Player Interaction)

PieceBehaviour.OnPointerDown → InputHandler.BeginDrag(this) ← fails if blocked or another drag active → BoardController.Lift(this) ← removes piece from occupancy map → SetDragging(true) ← scale up, show snap dots (DOTween fade) PieceBehaviour.OnDrag → transform.position = ScreenToWorld(pointer) + _dragOffset PieceBehaviour.OnPointerUp → SnapSystem.TrySnap(this) → BoardController.GetNearestFreeSnapPoint(anchorWorldPos) [O(1) round] → distance check (squared, threshold = 0.5 × cellSize) → BoardController.Place(piece, snapPoint) → GetTargetTriangles: validate + build target list → mark _occupiedTriangles[], update _filledTriangles → CheckCompletion() → piece.SetPlaced(targetPos) ← DOTween snap animation → raise OnMoveExecuted(PlacePieceCommand) → GameManager pushes command onto Stack<ICommand> → [on snap failure] piece.ReturnToTray(fromPos) ← DOTween return animation → InputHandler.EndDrag()

5.5 Level Completion

BoardController.CheckCompletion() → _filledTriangles == _totalTriangles → OnBoardCompleted.Invoke() GameManager.HandleBoardCompleted() → GameState = LevelComplete (blocks all input via InputHandler.IsBlocked) → UIOverlay.ShowCompletion() ← fade-in "Done" + "Tap to Continue" Player taps Next Level button → UIOverlay callback → GameManager.StartNextLevel() → BeginLevel(_currentConfig) ← same config, new seed

5.6 Undo

GameManager.UndoLastMove() → commandHistory.Pop() → PlacePieceCommand.Undo() → BoardController.Lift(piece) ← frees triangles → piece.ReturnToTray(_fromPosition) ← DOTween back to pre-snap position

6. Board System

6.1 BoardController

Owns three parallel data structures indexed by [row, col, type]:

  • bool[,,] _occupiedTriangles — fast free/occupied query
  • PieceBehaviour[,,] _occupants — reverse lookup (piece at triangle)
  • Dictionary<PieceBehaviour, List<(r,c,t)>> _pieceOccupancy — enables O(1) Lift

Snap-point grid: (N+1)² SnapPoint GameObjects sitting at every grid vertex. GetNearestFreeSnapPoint runs in O(1) by rounding the world position to the nearest integer grid coordinate — no distance iteration.

6.2 SnapPoint

Lightweight MonoBehaviour marking a grid vertex. Interior points (not on the board edge) display a faint white circle sprite generated at runtime from a procedurally drawn texture. A single shared Sprite is reused across all instances to avoid redundant texture allocations.

6.3 SnapSystem

On TrySnap: finds the nearest snap point, checks squared distance against a pre-computed threshold (0.5 × cellSize), then delegates placement to BoardController.Place. On success it raises OnMoveExecuted with a PlacePieceCommand ready to be pushed onto the undo stack.

7. Piece System

7.1 PieceFactory (static)

Converts PieceJson → PieceData. Translates absolute triangle flat-indices into piece-local TriOffset values by subtracting the anchor cell's (col, row). Parses HTML hex colours via ColorUtility, falling back to grey on parse failure.

7.2 PieceSpawner

Instantiates one PieceBehaviour prefab per PieceJson entry, positions it at its tray spawn coordinates, and calls AnimateIn(index) which triggers a staggered DOTween drop-in from above. Keeps an internal list for batch destruction on level clear. Resets the global sort-order counter (PieceSortOrder.Reset()) on destroy.

7.3 PieceBehaviour

The heaviest MonoBehaviour — responsible for all visual construction and pointer handling. Built in four steps during Initialize:

StepMethodWhat it produces
1BuildTriangleSprites() One child GameObject + SpriteRenderer per triangle, coloured via a shared MaterialPropertyBlock. Two triangle sprite textures (lower and upper) are generated once and shared across all piece instances.
2BuildCollider() PolygonCollider2D with one path per triangle, enabling Unity's EventSystem pointer events.
3BuildAnchorTransforms() A single anchor transform at localPosition (0,0) — the piece pivot IS the anchor vertex.
4BuildSnapDots() 1–4 white circle markers placed at interior vertices (vertices shared by ≥2 of the piece's own triangles). Invisible at rest; fade in while dragging.

Pointer event flow

  • OnPointerDown — gates through InputHandler, lifts piece off board, enables drag visuals.
  • OnDrag — moves transform.position to pointer + drag offset; uses a cached Vector3 buffer to avoid per-frame heap allocation.
  • OnPointerUp — calls SnapSystem.TrySnap; returns to tray if snap fails.

8. Input System

8.1 InputHandler

A single-instance gatekeeper. BeginDrag returns false if IsBlocked (set to true on level complete) or if another drag is already active, ensuring only one piece moves at a time. Stores a DragState (piece reference + pointer ID) as the active drag.

8.2 DragState

Plain data object — holds the dragging PieceBehaviour and the pointer ID used to identify the owning touch/mouse event. No MonoBehaviour inheritance.

9. UI System

UIOverlay wires up four difficulty buttons and one "Next Level" button. All interaction logic is delegated back to GameManager via System.Action callbacks set during Awake — UIOverlay has no direct reference to GameManager. Completion feedback uses DOTween fade-ins on two TMP_Text elements with a configurable stagger delay.

10. Command System (Undo)

ICommand declares Execute() and Undo(). PlacePieceCommand captures the piece, board reference, pre-snap world position, post-snap world position, and snap point at the moment of placement. Undo() calls BoardController.Lift + piece.ReturnToTray. GameManager maintains a Stack<ICommand> cleared on every new level.

11. Procedural Generation

Handled by LevelGenerator (MonoBehaviour) and TrianglePartitioner (plain C# class). The full algorithm is described in the companion document ProceduralGeneration_Algorithm.html. In brief:

  1. Randomised BFS flood-fill partitions the triangle grid into connected regions.
  2. Post-processing merges regions that violate piece-count constraints.
  3. Each region becomes one piece; colours are assigned from a shuffled 16-colour palette (Fisher-Yates) ensuring no duplicate colours within a level.

13. Level Editor (Unity Editor Only)

LevelEditorWindow (in Scripts/Editor/) provides an in-editor tool for painting hand-crafted levels. Output is a LevelData JSON file consumable by the TextAsset[] handmade level path.

This window is wrapped in #if UNITY_EDITOR and is excluded from all builds.

15. Performance Notes

  • O(1) snap lookup — GetNearestFreeSnapPoint rounds world position to grid coordinates; no iteration.
  • Shared sprites — two triangle sprites and one circle sprite are generated once and shared across all instances via static Sprite fields.
  • MaterialPropertyBlock — piece colour is applied via a MaterialPropertyBlock to avoid instancing separate Material objects.
  • Pre-squared threshold — snap distance check uses SqrMagnitude vs. a pre-squared threshold to avoid a sqrt per frame.
  • Cached Vector3 buffer — PieceBehaviour.ScreenToWorld reuses a single Vector3 field during drag to avoid per-frame heap allocation.
  • Reused candidate list — BuildSnapDots reuses a pre-allocated List<> field instead of creating four throwaway lists.
  • Cached camera Z — _cameraZ is read once at Initialize since the camera never moves.
