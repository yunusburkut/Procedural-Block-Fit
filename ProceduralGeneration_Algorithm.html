Blokfit — Procedural Level Generation

Algorithm design reference  ·  Blokfit Unity Puzzle Project  ·  2026-03-31

1. Overview

Blokfit is a 2D puzzle game in which the player drags irregularly shaped pieces onto a triangulated board. Every level is procedurally generated at runtime from a DifficultyConfig ScriptableObject, producing a complete LevelData object that partitions an N × N triangle grid into non-overlapping, connected regions — one region per puzzle piece.

The pipeline runs in three sequential phases:

  1. Grid encoding — map every triangle to a unique integer (flat index).
  2. Flood-fill partitioning — greedily claim triangles into connected regions via randomised BFS.
  3. Constraint enforcement — merge regions until piece-count and piece-size constraints are satisfied.

Two C# classes implement the pipeline:

  • TrianglePartitioner — handles phases 1 and 2.
  • LevelGenerator : MonoBehaviour — orchestrates phase 3 and assembles the final LevelData.

2. Difficulty Tiers

Three DifficultyConfig ScriptableObject assets drive the generator. Each config defines grid size, piece-count bounds, and piece-size bounds (in squares; multiplied by 2 internally to get triangle counts).

Difficulty Grid (N×N) Triangles (N²×2) minPieces maxPieces minPieceSize (sq) maxPieceSize (sq)
Easy 4 × 4 32 5 8 2 3
Medium 5 × 5 50 6 10 2 4
Hard 6 × 6 72 8 12 3 5
All values comply with the project spec: piece count in [5, 12] and grid size in [4, 6].

3. Level Output Format (JSON)

The generated level is serialised as JSON via Unity's JsonUtility (LevelSerializer.ToJson / FromJson). Levels can be downloaded from a remote server using UnityWebRequest; if the download fails the game falls back to procedural generation transparently.

Server download path

GameManager constructs the URL as: 

"{_serverBaseUrl}/{config.difficultyName}.json"
// e.g. https://example.com/levels/hard.json

If _serverBaseUrl is empty the generator runs locally. On HTTP error it falls back to procedural generation and logs a warning.

4. Phase 1 — Triangle Grid Encoding

Flat-index formula

Each square cell at position (col, row) is split by a / diagonal into two triangles. Every triangle gets a unique integer called its flat index: 

flat = (row × N + col) × 2 + type

  type 0 → lower triangle  (vertices: BL, BR, TR)
  type 1 → upper triangle  (vertices: BL, TR, TL)

Inverse:
  col  = (flat / 2) % N
  row  = (flat / 2) / N
  type =  flat % 2

An N=4 grid has 32 triangles (indices 0–31); N=6 has 72 (indices 0–71).

N = 4 → 32 triangles (flat indices shown) col 0 1 2 3 ┌────────┬────────┬────────┬────────┐ row ╱ 1 │ ╱ 5 │ ╱ 9 │ ╱ 13│ 3 ╱ 0 │ ╱ 4 │ ╱ 8 │ ╱ 12│ ├────────┼────────┼────────┼────────┤ ╱ 3 │ ╱ 7 │ ╱ 11│ ╱ 15│ ╱ 2 │ ╱ 6 │ ╱ 10│ ╱ 14│ ├────────┼────────┼────────┼────────┤ ╱ 17│ ╱ 21│ ╱ 25│ ╱ 29│ ╱ 16│ ╱ 20│ ╱ 24│ ╱ 28│ ├────────┼────────┼────────┼────────┤ ╱ 19│ ╱ 23│ ╱ 27│ ╱ 31│ ╱ 18│ ╱ 22│ ╱ 26│ ╱ 30│ └────────┴────────┴────────┴────────┘ lower(col, row) = (row*4 + col)*2 (even indices) upper(col, row) = (row*4 + col)*2 + 1 (odd indices)

Adjacency rules

Each triangle has at most 3 neighbours — one across the diagonal, two across edges. Boundary triangles have fewer.

TriangleNeighbour 1Neighbour 2Neighbour 3
lower(col, row) upper(col, row) — / diagonal upper(col, row−1) — bottom edge upper(col+1, row) — right edge
upper(col, row) lower(col, row) — / diagonal lower(col, row+1) — top edge lower(col−1, row) — left edge

5. Phase 2 — Randomised BFS Flood-Fill

TrianglePartitioner.CarveRegion(seedFlat, targetSize) grows one connected region from a seed triangle using Breadth-First Search. The key twist is that the (at most 3) free neighbours of each dequeued node are shuffled before being enqueued, producing organically shaped, non-stripe-like pieces.

Algorithm pseudocode

// Pre-allocated fields — zero heap allocations per call:
_carveResult : List<int>    // accumulated region members
_carveQueue  : Queue<int>   // BFS frontier
_neighborBuffer : List<int> // max 3 candidates, reused

procedure CarveRegion(seedFlat, targetSize):
    Mark seedFlat as assigned
    result ← [seedFlat];  queue ← [seedFlat]

    while queue not empty and |result| < targetSize:
        current   ← queue.Dequeue()
        neighbors ← GetFreeNeighbors(current)   // ≤ 3 unassigned
        Shuffle(neighbors)                        // Fisher-Yates in-place

        for each neighbor in neighbors:
            if |result| ≥ targetSize: break
            Mark neighbor as assigned
            result.Add(neighbor)
            queue.Enqueue(neighbor)

    return result.ToArray()
Why shuffle neighbours? Without shuffling, BFS always expands in the same direction, producing elongated stripe pieces. Shuffling the 1–3 candidates before enqueue makes the expansion direction random at every step → compact, irregular, organic shapes.

Seed scan — cursor-based O(T) search

HasUnassigned(out int seedFlat) finds the next unclaimed triangle using a forward-only integer cursor _nextSeedCursor. Because triangles are claimed in BFS order (not flat-index order), the cursor never needs to backtrack: 

// O(T) total across all calls — cursor only moves forward
while _nextSeedCursor < _total:
    if !_assigned[_nextSeedCursor]:
        seedFlat ← _nextSeedCursor
        return true
    _nextSeedCursor++
return false    // all triangles assigned

The naïve alternative — restarting from index 0 every call — would cost O(T²/avg) total. The cursor reduces this to O(T) amortised.

6. Phase 3 — Constraint Enforcement

After all triangles are claimed the region list may violate two constraints. LevelGenerator corrects both by merging regions.

6a. Inline small-region merge (during partitioning)

A freshly carved region that is smaller than minPieceSize × 2 triangles and the total count already exceeds minPieces is immediately merged into its geometrically nearest neighbour: 

if region.Length < minTriSize and regions.Count > config.minPieces:
    nearest ← FindNearestRegion(region, regions, n)
    if nearest ≠ null:
        MergeRegions(regions, region, nearest)

6b. Post-pass: reduce to maxPieces

After all triangles are assigned, if the count still exceeds maxPieces, the smallest region is repeatedly merged into its nearest neighbour until the count is within bounds: 

while regions.Count > config.maxPieces:
    MergeSmallestIntoNearest(regions, n)

Nearest-neighbour by centroid distance

"Nearest" means the region whose grid-space centroid is closest (squared Euclidean distance — no sqrt needed for comparison). Centroids are computed lazily and cached in a Dictionary<int[], Vector2> keyed by array reference (not value equality). When two regions merge, both old keys are evicted; the new merged array will recompute its centroid on first access. 

// Centroid of a region (grid-space coordinates):
centroid.x = mean of (flat / 2) % N    // column
centroid.y = mean of (flat / 2) / N    // row

// Nearest-region search — O(R) per call:
for each other in regions (skip self):
    d = SqrMagnitude(centroid(region) − centroid(other))
    if d < bestDist: best ← other

// Cache invalidation on merge:
_centroidCache.Remove(from)
_centroidCache.Remove(into)
// merged array reference is new → recomputed lazily on next access

7. Piece Assembly

Each final region is converted to a PieceJson record:

FieldHow it is set
cellsThe flat-index array of the region, exactly as produced by CarveRegion.
anchors[0]Minimum flat index in cells — the top-left-most triangle, used by the snap system as the placement reference point.
colorHex string from a per-level Fisher-Yates–shuffled 16-colour palette (colours are ~22° apart on the hue wheel). Assigned with i % 16 so each piece gets a unique hue for up to 16 pieces.
spawnX / spawnYUniform random scatter within _traySpread radius around _trayCenter (defaults to world position (0, −2.4)).

8. Referenced Algorithms

AlgorithmWhere usedPurpose
Breadth-First Search (BFS) TrianglePartitioner.CarveRegion Guarantees every carved region is topologically connected (no orphaned triangles).
Fisher-Yates Shuffle TrianglePartitioner.Shuffle<T> & LevelGenerator.ShuffledPalette Uniform-random permutation in O(n) time. Used for neighbour ordering (shape variety) and colour assignment (no repeated hues).
Greedy Nearest-Neighbour Merge LevelGenerator.FindNearestRegion + MergeRegions Constraint-satisfying region merge that keeps merged shapes spatially compact rather than merging across the board.
Lazy Memoisation (Dictionary cache) LevelGenerator.GetCentroid Avoids redundant O(|region|) centroid summation across repeated nearest-neighbour queries. Invalidated on merge.
Cursor-based linear scan TrianglePartitioner.HasUnassigned O(T) amortised seed search — cursor advances forward only, never backtracks. Replaces naïve O(T²) re-scan.
Seeded PRNG (System.Random) Entire pipeline Reproducible level generation: identical seed → identical layout. Seed defaults to Environment.TickCount for truly random levels.
Pre-allocated reusable buffers _carveResult, _carveQueue, _neighborBuffer Eliminates per-call heap allocations inside the hot BFS loop, reducing GC pressure during generation.

10. Complexity Summary

Phase / OperationTimeSpace
Triangle adjacency queryO(1)O(1)
HasUnassigned (all calls combined)O(T) amortisedO(1)
CarveRegion (single call)O(targetSize)O(1) — reused buffers
All CarveRegion calls combinedO(T)O(T) — _assigned array
Centroid computation (amortised via cache)O(T) totalO(R) — cache entries
Post-merge passO(R² · S̄)O(1) extra
OverallO(T + R² · S̄)O(T)

T = N²×2 triangles, R = final piece count (≤ maxPieces ≤ 12), S̄ = average piece size.
For the largest supported grid (N=6, T=72, R≤12) the entire pipeline completes in well under 1 ms.
